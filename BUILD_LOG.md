# Build Log

How this site is built and maintained, and the judgment calls made along the way. Written because the process is arguably as on-brand as the content — a small, honest case study in directing AI-assisted engineering with real human checkpoints, not letting it run unsupervised.

## Stack and pipeline

- `index.php` is the single hand-edited source. `index.html` is generated by running `php -f index.php > index.html` — PHP's only job here is stripping `<?php /* ... */ ?>` dead-comment blocks left over from an earlier template; there's no other server-side dependency anywhere in the stack.
- Both project showcase grids (AI & Governance Projects, Other Projects) are a single hand-rolled vanilla-JS module, `assets/js/project-grid.js` — no framework, no build step, and critically, no jQuery. They share one modal/lightbox and one flat, global `#<n>` hash index across both sections.
- Deployed straight from git to both Netlify and Cloudflare Pages — no build step on either host.
- A GitHub Action (`.github/workflows/build-html.yml`) that would regenerate `index.html` on push remains blocked by a PAT scope issue (pushing to `.github/workflows/*` needs the `workflow` scope, which the repo's token doesn't have) — `index.html` is rebuilt manually and checked by the smoke test before every commit instead (see Testing, below).

## The jquery-elastic-grid rewrite

The site originally ran both project grids through a single vendored jQuery plugin, `jquery-elastic-grid`, 2013-era and unmaintained. It was replaced entirely (both sections, ~23KB of plugin JS + its dependent modernizr/classie/elastislide/hoverdir scripts + CSS deleted from the repo) after three real, compounding problems surfaced:

- **Title text was hover-only.** The plugin rendered each project's title as a `<figure><span>` invisible until `:hover` — unusable on touch, and a real accessibility/SEO regression (the text exists in the DOM but is suppressed by default).
- **No native "featured" or size-variant support.** Highlighting Command Deck and the Quant platform required a DOM-patch hack bolted on after the plugin's own render pass, rather than a first-class field on the data.
- **A real, silent filter bug.** The plugin slugifies tag text into a CSS class with a plain `String.replace(' ','-')` — no `/g` flag, so it only replaces the *first* space. The original "Cloud & DevOps" tag has two spaces (around the `&`), so the class applied to project items and the class the filter button checked for silently diverged — the filter always returned zero results, no console error. Caught and worked around twice (renaming tags to avoid the second space) before deciding the underlying plugin, not the tag names, was the actual problem.

The replacement is a ~600-line vanilla-JS module (mostly project data, not logic): CSS Grid for layout, a shared modal for the detail/gallery view (image prev/next, captions, Live/GitHub buttons — everything the plugin's expanding preview did), always-visible card titles + one-line summaries + tag chips, and a native `featured` boolean (with an explicit `featuredOrder` tiebreak) instead of a DOM patch.

## Tag taxonomy — two, deliberately different

Went through several real revisions. Started at 15 sprawling, inconsistent tags (`AI/ML`, `Python`, `LangGraph`, `AWS`, `Security`, `DevOps`, `RAG`, `Product`, `Web`, `ERP`, `CMS`, `Mobile app`, `UI/UX design`, `E-commerce`, `Trading`), which made the filter bar meaningless. Collapsed to a 5-tag set shared across all projects — but even that broke down once "AI Governance" ended up matching every single item in its own section: a filter that returns 100% of the set for its headline tag isn't filtering anything.

The current taxonomy is two separate, purpose-built vocabularies, one per grid:

- **AI & Governance Projects** filters by *governance mechanism* — `Human-in-the-Loop Checkpoints`, `Deterministic Gates over LLM Judgment`, `Structural Anti-Hallucination`, `Automated Compliance Gating` — mapping 1:1 onto the four pillars in "AI Governance Philosophy" above, so the filter doubles as a live index into the site's own stated framework. 1–2 projects per tag, so clicking one actually changes what's on screen.
- **Other Projects** filters by *domain* — `Enterprise Systems`, `E-Commerce & Payments`, `CMS & Web Platforms`, `Mobile & Product Design` — deliberately a different axis from the AI section's vocabulary, so the two filter bars don't feel like the same control twice. Both navs show per-tag item counts.

## Screenshots

Cover thumbnails follow the same convention the original template already used for its legacy projects (e.g. `dsj/front_thumb.PNG`, `erp/accounting_dashboard_thumb.PNG`) — a tight square close-up of the most visually distinctive real content, not a full-page overview. Full-page screenshots exist too, as the 2nd+ images in each card's gallery.

All screenshots are real, captured live via Playwright, not stock art or mockups:

- Two of the apps (Streamlit Community Cloud, Hugging Face Spaces) auto-sleep on their free tier after inactivity — capturing them meant clicking the wake/restart button and waiting 30–90s for a real boot, not just hitting the URL.
- Hugging Face Spaces embed the actual app in an iframe at `https://<user>-<space>.hf.space/`, separate from the `huggingface.co/spaces/...` page — interacting with the app (not just screenshotting the loading chrome) meant navigating to the embed URL directly.
- For Change Impact Assessor, rather than screenshot the empty input form and call it done, ran an actual sample assessment through to completion to capture the real governance gate firing — "HIGH risk — pending human sign-off" with live Acknowledge/Discard buttons, not a description of what it would do.
- One redaction: a scroll position on the Quant platform's public GitHub README happened to include a real IBKR account number (already public, in an already-public repo). Cropped it out of the portfolio screenshot anyway — the repo being public doesn't obligate the portfolio to amplify it. Small decision, but it's the same instinct the site's own "AI Governance Philosophy" section describes, applied to something as mundane as picking a screenshot's scroll position.

## Positioning

The header, About Me, and project ordering were rewritten mid-build to lead with AI governance rather than treat it as one of several co-equal pillars, in response to a real (and at the time undisclosed) job offer. Specific employer name and start date were deliberately kept off every file touched during that window — the site's copy changed to reflect a shift in priorities without leaking information that wasn't public yet.

## Testing

`tests/smoke_test.py` runs before every commit that touches either grid, `index.php`, `main.js`, `project-grid.js`, or `custom.css`. It rebuilds `index.html` from `index.php`, serves the repo with PHP's built-in server, and drives the real page with Playwright through 23 checks: exact card counts and filter-tab/count distribution for both sections, filtering actually narrowing the visible set, the shared modal + gallery navigation + `#<n>` hash deep-linking across both sections, featured projects sorting first in the right order, the dark-mode toggle's jQuery-dependent GitHub-logo swap (the one place jQuery is still load-bearing — dark-mode-switch.js genuinely calls `$()`, confirmed before assuming it was safe to drop entirely), and zero unexpected console errors or failed network requests. Verified it's a real regression gate, not a rubber stamp, by deliberately breaking a featured flag mid-build and watching it fail with the right diagnostic before reverting.

## Infrastructure

Cloudflare sits in front of the Netlify origin for DNS, WAF, and bot management — `server: cloudflare` on every response — but per the actual response headers, it wasn't edge-caching the HTML at all (`cf-cache-status: DYNAMIC`, `cache-control: max-age=0, must-revalidate`); only static assets (JS/CSS/images) carry a 4-hour `max-age`. `deploy.ps1` pushes to `origin/carsonng` and then calls Cloudflare's purge-cache API, closing the gap for new/other visitors when a screenshot or script changes under the same filename — a real recurring pattern on a site with hand-captured, hand-named screenshots. It doesn't reach an individual visitor's own browser cache, which is a separate cache the purge API can't touch; that side of the gap self-resolves within the same 4-hour window regardless. Credentials (a Cloudflare API token scoped to `Zone:Cache Purge` on the `carsonng.com` zone only, plus the zone ID) live in `.env.local`, gitignored and never committed — `.env.local.example` documents the expected format.
